Privacy Policy

Effective date: 2026-08-26

OIDC Starter is a public demonstration of an open-source authentication starter. Morda Labs is the project name, not a separately registered legal entity. This page describes information handled when you use the hosted demo.

Information is used to authenticate visitors, secure sessions, display profile claims, diagnose technical issues, and respond to user requests.

Authentication and profile information

Production offers Keycloak through OpenID Connect, Google, and GitHub sign-in. The staging provider endpoint also advertises Facebook; Facebook is not enabled in production. A provider may send information needed for sign-in, such as an account identifier, name, username, email address, role claims, email-verification status, or profile picture URL. Displaying a profile image URL may cause your browser to request the image from an external host.

The ASP.NET Core BFF uses this information to establish a session. Its current-user API exposes normalized identity and profile information to the browser, but not provider tokens. The demo has no separate application database dedicated to normalized user profiles.

Keycloak is a persistent identity service backed by PostgreSQL. Its shared, publicly documented demo account is used by multiple visitors and does not give each visitor an independent private identity. Keycloak user registration is disabled; individual Keycloak accounts can be deleted administratively.

Google user data

Google may provide basic identity information available under the configured sign-in scopes, including an account identifier, name, email address, email-verification status, and profile picture URL. The demo uses it for sign-in and the current-user profile.

Sessions, cookies, and tokens

The BFF uses protected authentication cookies for sessions and antiforgery cookies to protect requests such as logout. The authentication cookie is configured as HTTP-only and secure. An antiforgery request cookie is readable by browser code so it can send the request token.

Built-in OpenID Connect explicitly saves tokens in the protected authentication ticket. GitHub explicitly disables token saving; Google and Facebook normally use the framework default of not saving tokens. Token handling can depend on configuration, so this is not a guarantee about every deployment or provider.

Browser preference

Your language choice is stored in your browser's localStorage under oidc-starter.public-demo.locale. You can remove it through your browser's site-data controls.

Infrastructure, logs, and backups

The demo runs on OVH-hosted infrastructure. Technical server and container logs may record requests, errors, and related connection information. Keycloak user and admin event persistence is disabled in the audited deployments, but this does not mean server logs are absent. Docker uses json-file logging; a log rotation limit has not been confirmed.

OVH Automated Backup is active and displays a seven-day restoration window. The exact backup scope and database recovery consistency have not been verified. We cannot promise that a deletion immediately removes copies from logs or backups.

Authentication sessions expire according to session settings. Keycloak identities, technical logs, backups, and contact emails are separate records whose retention does not follow session expiration; no fixed retention period is stated for them here.

Third-party providers

When you choose an external identity provider, it handles your account and sign-in under its own policies. Signing out of the demo does not delete your provider account or all information held by the demo. See Data Deletion for how to make a request.

Your requests and contact

To ask about your information or request access, correction, deletion, or another applicable data-subject right, email contact@mordalabs.com. Requests are handled manually. Contact messages are forwarded to an OVH-hosted mailbox. For security reports, email security@mordalabs.com.
