Premium Sessions

Autorytatywna kontrola operacyjna nad lokalnymi sesjami ASP.NET Core BFF, zbudowana na otwartej podstawie OIDC Starter.

Wypróbuj demo na żywo Porozmawiaj o ewaluacji Przegląd Premium

Aktualny moduł

Kontroluj lokalną sesję po zalogowaniu.

Autorytatywne sesje

Przechowuj stan chronionego biletu uwierzytelnienia na serwerze w autorytatywnym magazynie sesji.

Wgląd w aktywne sesje

Pobieraj aktywne lokalne sesje dla dokładnie określonego, zaufanego zakresu tożsamości OIDC, z bezpiecznymi metadanymi i nieprzezroczystymi identyfikatorami.

Unieważnij jedną sesję

Zakończ wybraną lokalną sesję, aby jej dotychczasowy plik cookie przeglądarki nie uprawniał już do chronionych żądań.

Unieważnij wszystkie sesje

Unieważnij zestaw aktywnych lokalnych sesji w tym samym zaufanym zakresie tożsamości. Nie kończy to sesji u dostawcy ani nie uniemożliwia ponownego zalogowania.

Koordynacja przez współdzielony magazyn

Redis koordynuje autorytatywny stan między instancjami BFF; aplikacja hostująca zapewnia też współdzielone, trwałe klucze ASP.NET Core Data Protection.

Wylogowanie u dostawcy

Zgodny ze standardem OIDC Back-Channel Logout może unieważniać pasujące lokalne sesje dla jawnie skonfigurowanych, obsługiwanych dostawców.

Granica zaufanej tożsamości

Kontrola Core niezależna od dostawcy, oparta na zweryfikowanej tożsamości OIDC.

Premium Sessions Core nie jest rozwiązaniem wyłącznie dla Keycloak. Korzysta z dokładnego, zaufanego powiązania ProviderId, Issuer, ClientId i Subject pochodzącego z prawidłowo zintegrowanego logowania OIDC. Przeglądarka nie określa tego zakresu uprawnień.

Bezpośrednie integracje OIDC zgodne ze standardem mogą korzystać z przekazywania zweryfikowanych metadanych przez OSS. OIDC z pośrednikiem wymaga oceny granicy tożsamości i powiązania kont po stronie pośrednika. Same integracje OAuth i własne mechanizmy inne niż OIDC nie są automatycznie objęte obsługą.

Zbuduj lub wykorzystaj ponownie

Utrzymania wymaga łączne działanie tych elementów.

Doświadczone zespoły mogą wdrożyć te elementy. Premium łączy ich działanie w pakiet do ponownego użycia w projektach BFF, ograniczając powtarzanie projektowania i testów regresji.

  • Izolacja według zaufanego dostawcy, wystawcy, klienta i identyfikatora użytkownika oraz bezpieczna przenośność między dostawcami.
  • Autorytatywny stan biletu, odrzucanie nieaktualnych plików cookie, unieważnianie pojedynczych i wielu sesji oraz poprawna obsługa wyścigu odnowienia i unieważnienia.
  • Koordynacja Redis i Data Protection między instancjami oraz osobno konfigurowana integracja Back-Channel Logout.

Integracja dla programistów

Interfejs .NET dla aplikacji hostującej.

Pakiet w prywatnej wersji próbnej to OidcStarter.Premium.Sessions 0.1.0-preview.1 dla .NET 9. Zależy od opublikowanego pakietu OSS BFF. Dostęp do niego jest uzgadniany z zatwierdzonymi osobami testującymi; nie jest publicznym wydaniem w NuGet.

AddPremiumSessions(...) rejestruje IPremiumSessionControl do pobierania sesji w dokładnie określonym zakresie oraz unieważniania jednej lub wszystkich sesji. Aplikacja hostująca uwierzytelnia i autoryzuje wywołujących; Premium nie udostępnia ogólnego punktu HTTP do administracji.

Przykład rejestracji

builder.Services.AddPremiumSessions(
    CookieAuthenticationDefaults.AuthenticationScheme)
    .UseRedis(redisConnection, options =>
    {
        options.KeyPrefix = "myapp:premium:sessions:v3";
        options.ActiveSessionTtl = TimeSpan.FromHours(8);
        options.MinimumRevokedTombstoneRetention =
            TimeSpan.FromMinutes(30);
    });

redisConnection jest zarządzany przez aplikację hostującą. Udostępnia ona trwałe klucze Data Protection i nazwę aplikacji wszystkim instancjom. Autoryzowane usługi aplikacji uzyskują IPremiumSessionControl przez wstrzykiwanie zależności.

Wyniki i ograniczenia

Zweryfikowane działanie z uwzględnieniem granic dostawców.

Kontrola lokalnych sesji

W istniejącym demo zweryfikowano pobieranie aktywnych sesji, dwie równoczesne sesje przeglądarki dla jednego konta, unieważnienie wybranej sesji bez wpływu na drugą, odrzucenie unieważnionego pliku cookie oraz unieważnienie wszystkich sesji.

Wyniki dla dostawców i wielu instancji

Bezpośrednia integracja Google OIDC potwierdziła przenośność Core w udokumentowanej konfiguracji próbnej. Back-Channel Logout zweryfikowano osobno z Keycloak. Działanie wielu instancji ze współdzielonym Redis i Data Protection sprawdzono na poziomie integracji repozytorium.

Te wyniki nie stanowią certyfikacji dostawców, wszystkich konfiguracji Google, powszechnej zgodności z OIDC, Google Back-Channel Logout ani wdrożenia produkcyjnego. Lokalne unieważnienie nie oznacza globalnego wylogowania u dostawcy tożsamości ani wyłączenia konta.
