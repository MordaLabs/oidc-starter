Privacy Policy

Effective date: 2026-08-26

OIDC Starter is a public demonstration of an open-source authentication starter operated by Morda Labs. This policy describes information handled when you use this live demo.

Authentication and profile information

You can sign in only through authentication providers configured for the demo. These may include an OpenID Connect provider and, when enabled, Google, GitHub, or Facebook. The provider may send identity and profile information needed for sign-in, such as a subject identifier, name, username, email address, role claims, and provider metadata such as email-verification status or a profile picture URL.

The demo can display the current authenticated user's normalized profile and provider information in the browser. It does not include an application database or separate user-profile store in this demonstration.

Google user data

When Google login is used, Google may provide basic identity and profile information available under the configured sign-in scopes, such as a subject or account identifier, name, email address, email-verification information, and profile picture URL.

The demo uses this information to establish the authenticated session and show the normalized current-user profile. Google access and refresh tokens are not exposed to browser JavaScript, and the Google authentication handler does not save provider tokens.

The public demo has no separate application database or dedicated user-profile store for this profile information. The OIDC Starter demo does not implement functionality that sends the normalized Google profile to unrelated third-party services.

Sessions, cookies, and tokens

The demo uses an ASP.NET Core BFF session. Essential technical cookies establish and protect the authenticated session, support the sign-in flow, and provide antiforgery protection for logout. The main session cookie is configured as HTTP-only and secure, so browser JavaScript cannot read it.

The current-user endpoint returns normalized identity and profile information; it does not return provider access tokens or refresh tokens to the browser. For the built-in OpenID Connect flow, authentication tokens are retained in the protected authentication ticket. The starter's Google, GitHub, and Facebook handlers do not save provider tokens.

Third-party providers

When you choose an external identity provider, that provider processes your authentication according to its own privacy policy and terms. Morda Labs does not control those providers' practices.

Questions and security reports

For privacy questions or other contact about this demo, email contact@mordalabs.com. To report a security issue with the demo, email security@mordalabs.com.

Updates to this policy.

We may update this page as the public demo changes. The effective date above shows when it was last updated.
