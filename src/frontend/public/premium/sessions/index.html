Premium Sessions

Authoritative operational control over local ASP.NET Core BFF sessions, built on the open-source OIDC Starter foundation.

Try live demo Discuss an evaluation Premium overview

Current module

Control the local session after sign-in.

Authoritative sessions

Keep protected authentication ticket state on the server in an authoritative session store.

Active-session visibility

Query active local sessions for an exact trusted OIDC identity scope, with safe metadata and opaque handles.

Revoke one

End one selected local session so its existing browser cookie no longer authorizes protected requests.

Revoke all

Revoke the snapshot of active local sessions in the same trusted identity scope. This does not end the upstream provider session or prevent future sign-in.

Shared-store coordination

Redis coordinates authoritative state across BFF instances; the host also provides shared persistent ASP.NET Core Data Protection keys.

Upstream logout

Standards-based OIDC Back-Channel Logout can revoke matching local sessions for explicitly configured, supported providers.

Trusted identity boundary

Provider-neutral Core control, anchored in validated OIDC identity.

Premium Sessions Core is not Keycloak-specific. It uses the exact trusted ProviderId, Issuer, ClientId, and Subject binding from a correctly integrated OIDC sign-in. A browser does not supply that authorized scope.

Standards-compliant direct OIDC integrations can use the OSS validated metadata handoff. Brokered OIDC requires evaluation at the broker's identity and account-linking boundary. OAuth-only or custom non-OIDC handlers are not automatically covered.

One application boundary

  1. Browser
  2. OSS BFF authentication and session
  3. Premium Sessions authoritative control
  4. Shared Redis store

The host authorizes control callers, owns Redis and Data Protection configuration, and decides deployment policy.

Build or reuse

The combined behavior is the maintenance work.

Capable teams can implement these pieces. Premium packages their combined behavior for reuse across BFF projects instead of repeatedly designing and regression-testing it.

  • Trusted provider, issuer, client, and subject isolation with safe provider portability.
  • Authoritative ticket state, stale-cookie rejection, selective and bulk revocation, and renewal/revocation race correctness.
  • Shared Redis and Data Protection coordination across instances, with separately configured Back-Channel Logout integration.

Developer integration

A host-facing .NET API.

The private preview package is OidcStarter.Premium.Sessions 0.1.0-preview.1 for .NET 9. It depends on the published OSS BFF package. Package access is arranged for approved evaluators; it is not a public NuGet release.

AddPremiumSessions(...) registers IPremiumSessionControl for exact-scope query, revoke-one, and revoke-all. The host authenticates and authorizes callers; Premium does not provide a generic administration HTTP endpoint.

Registration shape

builder.Services.AddPremiumSessions(
    CookieAuthenticationDefaults.AuthenticationScheme)
    .UseRedis(redisConnection, options =>
    {
        options.KeyPrefix = "myapp:premium:sessions:v3";
        options.ActiveSessionTtl = TimeSpan.FromHours(8);
        options.MinimumRevokedTombstoneRetention =
            TimeSpan.FromMinutes(30);
    });

redisConnection is host-owned. The host shares persistent Data Protection keys and application name across instances. Authorized host services resolve IPremiumSessionControl through dependency injection.

Evidence and limits

Verified behavior, with distinct provider boundaries.

Local session control

Active-session query, two concurrent browser sessions for one account, selective revoke, an unaffected sibling, rejection of the revoked cookie, and revoke-all were verified in the existing demo.

Provider and scale-out evidence

Direct Google OIDC proved Core portability with the recorded preview configuration. Keycloak separately verified Back-Channel Logout. Shared Redis and Data Protection scale-out was verified at repository integration level.

These results do not certify providers, every Google configuration, universal OIDC interoperability, Google Back-Channel Logout, or a production deployment. Local revocation is not global identity-provider logout or account disablement.
