How it works

From configured provider to application session

Your application owns the sign-in experience. OIDC Starter handles the selected provider flow and establishes the backend session.

  1. 1

    Discover providers

    The server exposes only the login providers registered by your application.

    /api/auth/providers

  2. 2

    Render your chooser

    Your frontend renders the returned providers using its own components and design system.

    provider.id

  3. 3

    Authenticate

    OIDC Starter challenges the selected provider and handles the callback on the server.

    login(provider.id)

  4. 4

    Use the session

    The frontend reads normalized user information from the application session.

    /api/auth/me

Practical boundaries

Authentication that stays legible

Server-side session

The browser uses the backend session instead of receiving provider tokens through the current-user response.

The package defaults to an HTTP-only, secure __Host- session cookie.

Provider-aware identity

The current-user contract includes provider provenance and normalized profile metadata without turning external profile data into authorization.

Unauthenticated current-user requests return 401.

Application-owned authorization

OIDC Starter provides authenticated-session policies, claim and scope helpers, and role-mapping foundations.

Your application still owns roles, tenant access, resource ownership, and business authorization decisions.

Auth endpoint boundaries

Public entry points, protected session data, and guarded state changes

The BFF exposes only the entry points needed to start authentication, read the application session, and safely end it.

Public entry points
  • GET /api/auth/providers
  • GET /api/auth/login
  • GET /api/auth/login/{provider}
  • GET /api/auth/csrf

These endpoints intentionally start discovery, login, or antiforgery initialization. Provider-specific login accepts only providers registered by the server application; unknown provider IDs are rejected.

Authenticated session identity
  • GET /api/auth/me

The endpoint returns the normalized current-user contract for an authenticated backend session and otherwise responds with 401 Unauthorized.

Guarded state change
  • POST /api/auth/logout

The package validates the ASP.NET Core antiforgery token and also checks Origin or Referer against trusted origins before completing logout.

The origin check is defense in depth; antiforgery validation is the primary CSRF protection.

Production responsibility

Production deployments still configure HTTPS, trusted frontend origins and reverse proxies, secret storage, cookie policy, and application-specific authorization.

Custom cookie-authenticated POST, PUT, PATCH, and DELETE endpoints should follow the same antiforgery contract.

Get started

Add OIDC Starter to your Angular + ASP.NET Core app

Start with the core ASP.NET Core BFF package. For Angular applications, optionally add the headless auth client to reduce integration code without imposing a user interface.

OIDC Starter provides one BFF integration surface for OpenID Connect and registered social login providers.

Core server package

ASP.NET Core BFF

The core OIDC Starter package provides the backend session, authentication endpoints, antiforgery integration, provider discovery, and authorization foundations.

Register only the login providers your application needs. Providers that are not registered are not offered by the runtime discovery endpoint.

OidcStarter.AspNetCore.Bff

Installation

dotnet add package OidcStarter.AspNetCore.Bff

Provider registration

builder.Services.AddOidcStarterBff(builder.Configuration);

var facebookSection = builder.Configuration.GetSection("ExternalLogin:Facebook");
if (facebookSection.GetValue<bool>("Enabled"))
{
  builder.Services.AddOidcStarterFacebook(facebookSection.GetSection("Options"));
}

var githubSection = builder.Configuration.GetSection("ExternalLogin:GitHub");
if (githubSection.GetValue<bool>("Enabled"))
{
  builder.Services.AddOidcStarterGitHub(githubSection.GetSection("Options"));
}

var googleSection = builder.Configuration.GetSection("ExternalLogin:Google");
if (googleSection.GetValue<bool>("Enabled"))
{
  builder.Services.AddOidcStarterGoogle(googleSection.GetSection("Options"));
}

Pipeline

app.UseOidcStarterBff();
app.MapControllers();

Enable only the providers your application uses. Credentials belong in deployment configuration or local User Secrets, not in this source snippet. The configured provider list is exposed through /api/auth/providers.

Optional headless Angular client

Angular BFF integration

Optional Angular services and typed contracts for applications using the OIDC Starter BFF. The package handles current-user loading, provider discovery, login redirects, logout, and antiforgery initialization without rendering a user interface.

Your application owns the buttons, modal, icons, layout, and styling.

login(providerId: string): void {
